# Subscription System

Multi-tier subscription system with database-enforced usage limits, org-level and user-level subscriptions, seat enforcement, and feature access gating.

## Architecture

The subscription system enforces usage limits at the database level using PostgreSQL functions. Limits are checked before resource creation and incremented after successful operations.

Two subscription levels coexist:
- **User-level**: For users in the default Mangrove org (`user_subscriptions` + `user_usage_counters`)
- **Org-level**: For users in personal orgs (`org_subscriptions` + `org_usage_counters`)

## Limit Enforcement

Limits are enforced via PostgreSQL functions that check counters before allowing resource creation:

- **Strategy creation**: Checks strategy count against tier limit
- **Backtest execution**: Checks monthly backtest count
- **API calls**: Tracks per-month API call volume
- **Token usage**: Monitors LLM token consumption

When a limit is exceeded, the API returns:

```json
{
  "error": "USAGE_LIMIT_EXCEEDED",
  "message": "Monthly backtest limit reached (5/5). Upgrade your plan for more backtests.",
  "code": "USAGE_LIMIT_EXCEEDED"
}
```

## Custom Tier

The Custom tier supports per-subscription limits for institutional customers with individually negotiated limits on all resources.
